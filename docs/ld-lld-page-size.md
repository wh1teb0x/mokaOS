# ld.lld の max-page-size 問題

## 概要

MikanOS の本の手順通りにカーネルをリンクすると、QEMU 上でカーネルが実行されない問題が発生する。
ローダーがカーネルの ELF ファイルをメモリに読み込んでエントリポイントにジャンプしても、正しいコードが存在しないアドレスを参照してしまう。

## 原因

LLD 12 以降でデフォルトの `max-page-size` が `0x1000`（4KB）に変更された。
これにより ELF セグメントがページ境界にアライメントされ、ファイル内のオフセットと仮想アドレスにずれが生じる。

### 具体例

```
.text セクション:
  ファイル内オフセット: 0x120
  仮想アドレス:        0x101120
```

ローダーが ELF ファイルを `0x100000` にそのまま読み込むと、コードは `0x100120` に配置される。
しかしエントリポイントは `0x101120` を指しているため、0x1000 バイトのずれが生じ、カーネルが正しく実行されない。

## 環境

- ld.lld: Ubuntu LLD 14.0.6
- OS: WSL2 (Linux 6.6.87.2-microsoft-standard-WSL2)

## 解決策

リンカフラグに `-z max-page-size=0x1` を追加する。

```makefile
LDFLAGS += --entry KernelMain -z norelro -z max-page-size=0x1 --image-base 0x100000 --static
```

これによりページアライメントが 1 バイトになり、ファイル内の配置と仮想アドレスが一致する。

## 参考

- MikanOS の本は LLD 10〜12 頃の環境で書かれたため、この問題は発生しなかった
- LLD 12 未満ではセグメントがファイル内で詰めて配置されるため、生ファイル読み込みでも動作する
